# Рабочая среда для разработки с ИИ-агентами (Claude Max + ChatGPT)

Сводный документ: как организовать кроссдевайсную рабочую среду с двумя нейросетями, общей памятью, доступом к серверам по SSH и git, а затем — как упаковать всё это в собственное расширение VS Code с кастомным UI.

---

## 1. Исходные требования

- Две максимальные подписки: **Claude Max** и **ChatGPT**.
- Много проектов; у каждого — приватный GitHub-репозиторий и свой сервер.
- Устройства на **macOS** и **Windows**.
- Нужно:
  - возвращаться в чат с любого устройства;
  - переключаться между нейросетями, и чтобы новая «видела» контекст прошлых чатов (даже чужих);
  - чтобы контекст при этом не забивался;
  - чтобы агент сам ходил на сервер по SSH и выполнял манипуляции;
  - чтобы агент сам работал с git: commit / push / pull.

---

## 2. Ключевая идея: память живёт в файлах репозитория, а не в чатах

Напрямую расшарить историю чатов между Claude и ChatGPT нельзя — это закрытые экосистемы. Решение: **источник правды — сам репозиторий**, а не переписка. Это же решает проблему раздутого контекста.

### Как это устроено

- В каждом проекте лежат файлы:
  - `CLAUDE.md` — автоматически читается Claude Code;
  - `AGENTS.md` — читается Codex (OpenAI) и рядом других агентов.
  - Можно вести один файл и сделать символьную ссылку на второй.
- Содержимое: архитектура проекта, адрес и способ доступа к серверу, как деплоить, соглашения по коду, что нельзя трогать.
- Папка `docs/journal/` (или `docs/decisions/`) — **журнал сессий**. В конце каждой рабочей сессии агент по команде «запиши итоги в журнал и закоммить» пишет краткое резюме: что сделано, что решено, что осталось.

### Что это даёт

- Любая нейросеть на любом устройстве, открыв проект, восстанавливает контекст за пару тысяч токенов вместо мегабайтов старой переписки.
- Переключение Claude ⇄ GPT становится бесшовным: оба читают одни и те же файлы.
- Журнал синхронизируется через git — значит, и между устройствами.

---

## 3. Инструменты: терминальные агенты вместо веб-чатов

| Подписка | Агент | Что умеет |
|---|---|---|
| Claude Max | **Claude Code** (терминал / IDE) | Сам выполняет команды, редактирует файлы, git, SSH. macOS и Windows. |
| ChatGPT | **Codex CLI** | Аналогичный терминальный агент от OpenAI. |

Оба живут в терминале, читают одни и те же файлы проекта и работают с git «из коробки» — просто выполняя обычные `git commit`, `git push`, `gh pr create` и т.д.

---

## 4. Кроссдевайс: центральный dev-сервер + tmux

Самая надёжная схема «вернуться в чат с любого устройства» — не синхронизировать сессии между машинами, а держать их в одном месте.

1. Завести недорогой **VPS** как рабочую станцию (или использовать один из проектных серверов).
2. На нём: клоны всех репозиториев, установленные Claude Code и Codex, **tmux**.
3. С любого устройства (Mac, Windows, телефон через Termius/Blink) — `ssh` на сервер, затем `tmux attach` → вы в той же сессии агента, которую оставили вчера с другого компьютера, с живой историей диалога.
4. Сессии tmux переживают разрыв соединения и живут неделями.

Запасной вариант без центрального сервера: работать локально на каждой машине, а состояние переносить через git (журнал в `docs/` + `git pull` при пересадке). Менее бесшовно, но работает.

> У Claude Code есть `claude --continue` / `--resume` для возврата к прошлым сессиям, но сессии хранятся локально на конкретной машине — поэтому вариант с tmux на сервере решает задачу лучше всего.

---

## 5. SSH к проектным серверам

Агенту не нужны специальные интеграции — он выполняет обычный `ssh`. Настройка на машине, где запущен агент:

```
# ~/.ssh/config
Host proj1
    HostName 1.2.3.4
    User deploy
    IdentityFile ~/.ssh/proj1_key
```

Дальше в `CLAUDE.md` / `AGENTS.md`:

> Прод проекта доступен как `ssh proj1`. Логи: `/var/log/app/`. Деплой: `ssh proj1 'cd /srv/app && ./deploy.sh'`.

Агент сам подключится и сделает нужное.

### Безопасность

- Для агента — **отдельный пользователь** на сервере с ограниченными правами (не root).
- **Не включать** режим полного автоодобрения команд для продакшн-серверов: подтверждение деструктивных действий должно оставаться за человеком.

---

## 6. Git

Оба агента коммитят, пушат и пуллят сами через терминальный git. Для PR — `gh` CLI. Отдельной настройки не требуется, кроме авторизации git/gh на рабочей машине (или центральном сервере).

---

## 7. Гигиена контекста

- **Одна сессия — одна задача.** Закончили фичу → итоги в журнал → новая сессия.
- Длинные сессии сжимать (в Claude Code — `/compact`).
- Всё долгоживущее знание переносить из чата в файлы. **Чат — рабочая область, файлы — память.**

---

## 8. Своё расширение VS Code: архитектура

Идея: не писать агентов самому, а сделать **оболочку** над готовыми CLI-агентами — свой UI, оркестрация двух агентов, общая память, история.

### 8.1. Три слоя

1. **Extension host** (TypeScript, Node.js) — мозг: запускает агентов, управляет сессиями, читает/пишет файлы памяти.
2. **Webview** — кастомный UI (React/Svelte/что угодно) в боковой панели или вкладке: чат, переключатель «Claude / GPT», список сессий, кнопки подтверждений. Связь с extension host — `postMessage`.
3. **Слой агентов** — два взаимозаменяемых бэкенда за одним интерфейсом.

### 8.2. Подключение подписок (важно!)

Не ходить в API напрямую (это отдельный биллинг по токенам), а **оборачивать CLI-агенты, залогиненные в подписки**.

**Claude — Claude Agent SDK** (`@anthropic-ai/claude-agent-sdk`, TypeScript):

- SDK оборачивает CLI Claude Code и подчиняется тем же переменным окружения, что и терминал. Один раз логинитесь через `claude` под аккаунтом Max — код получает полноценного агента: bash, правки файлов, git, стриминг событий, session id для возобновления.
- ⚠️ Если в окружении есть `ANTHROPIC_API_KEY` — он по приоритету перебивает подписку и уводит биллинг в pay-as-you-go. Ключа быть не должно.
- ⚠️ Правила тарификации Agent SDK в движении: Anthropic анонсировала вынос Agent SDK / `claude -p` из лимитов подписки в отдельный месячный кредит, затем приостановила изменение — на данный момент всё идёт из лимитов подписки. Перед стартом сверяйтесь с support.claude.com.
- Запасной вариант (гарантированно как обычный Claude Code): спавнить CLI напрямую — `claude -p "задача" --output-format stream-json` и парсить поток JSON-событий.

**ChatGPT — Codex CLI**: логинится через аккаунт ChatGPT, имеет неинтерактивный режим (`codex exec` с JSON-выводом) и TypeScript SDK. Точные имена пакетов и режимы — проверять в актуальной документации OpenAI.

### 8.3. Единый интерфейс бэкендов

```typescript
interface AgentBackend {
  start(prompt: string, opts: { cwd: string; resumeId?: string }): AsyncIterable<AgentEvent>;
}
// ClaudeBackend — через @anthropic-ai/claude-agent-sdk
// CodexBackend  — через codex SDK / spawn codex exec
```

Пример для Claude (упрощённо):

```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const msg of query({
  prompt: userMessage,
  options: {
    cwd: workspaceFolder,
    resume: savedSessionId,          // возобновление прошлой сессии
    permissionMode: "default",
    canUseTool: async (tool, input) => {
      // Агент хочет выполнить, например: ssh proj1 'systemctl restart app'
      // Показываем диалог подтверждения в webview, возвращаем allow/deny
      return await askUserInWebview(tool, input);
    },
  },
})) {
  webview.postMessage({ type: "agentEvent", payload: msg }); // стрим в UI
}
```

Колбэк разрешений (`canUseTool`) — готовая точка для вашего UI: вместо терминального «y/n» — карточка «Агент хочет выполнить на сервере: …» с кнопками; диффы правок — нативным diff-редактором VS Code.

### 8.4. Общая память между агентами (главная ценность расширения)

- Расширение владеет `CLAUDE.md` / `AGENTS.md` и `docs/journal/` в каждом репозитории.
- По кнопке «завершить сессию» (или автоматически) — агент пишет резюме сессии, расширение коммитит его в журнал.
- При старте новой сессии — с любым агентом — расширение подкладывает последние N записей журнала в системный промпт (у Agent SDK есть опции кастомизации промпта; для Codex — аналогично или первым сообщением).
- История чатов — JSONL-файлы (по файлу на сессию) + session id обоих агентов. Тогда «продолжить вчерашний диалог» работает независимо от модели: транскрипт всегда можно показать в UI, а нативное возобновление использовать при продолжении с тем же агентом.

### 8.5. SSH и git в расширении

Почти ничего делать не нужно: агенты выполняют `ssh`, `git`, `gh` сами через свой bash-инструмент, используя ключи машины, где запущен extension host. Задачи расширения:

- UI подтверждений (см. колбэк выше);
- опционально — allowlist безопасных команд в настройках, чтобы `git status` шёл без клика, а `rm -rf` и деплой — с подтверждением.

### 8.6. Кроссдевайс: VS Code Remote-SSH

В режиме **Remote-SSH** extension host исполняется на удалённом сервере, а не на ноутбуке:

- Ставите расширение на центральный VPS → все сессии агентов, история чатов, session id, залогиненные CLI живут там.
- Открываете VS Code на Mac или Windows → Remote-SSH к серверу → та же панель, те же чаты, продолжение с места разрыва. Синхронизировать ничего не нужно.
- Требование: хранить состояние в файлах на сервере (workspace или `context.globalStorageUri`), а не в памяти процесса.

### 8.7. Дорожная карта прототипа

1. `yo code` — скелет расширения с webview.
2. Прикрутить Claude Agent SDK, добиться стриминга ответа в свой webview-чат. ← *после этого шага уже есть рабочий прототип*
3. Колбэк разрешений с UI-подтверждениями.
4. Codex-бэкенд за тем же интерфейсом + переключатель моделей.
5. Журнал / общая память.
6. Переезд на Remote-SSH.

---

## 9. Итоговый стек

- **VPS + tmux** — единая точка входа со всех устройств.
- **Claude Code и Codex CLI** — взаимозаменяемые агенты по подпискам.
- **`CLAUDE.md` / `AGENTS.md` + журнал в git** — общая память между нейросетями и устройствами.
- **SSH-алиасы** — доступ агентов к проектным серверам.
- **Своё расширение VS Code** (webview + Agent SDK + Codex SDK + Remote-SSH) — всё то же самое, но в одном кастомном UI.
