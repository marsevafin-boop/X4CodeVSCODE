# Agent Hub — X4Code для VS Code

Оболочка над CLI-агентами в одном чате VS Code: **Claude** (Agent SDK, подписка
Claude Max) и **GPT (Codex CLI**, аккаунт ChatGPT) — с проектами, общей памятью,
подтверждениями операций и историей сессий.

## Мобильный доступ (Android)

Чат работает и с телефона — агенты при этом выполняются на компьютере, где
открыт VS Code с Agent Hub:

1. В VS Code: команда **«Agent Hub: Мобильный доступ»** (или иконка 📱 в
   заголовке панели) — включит сервер и покажет ссылки с QR-кодами.
2. На телефоне установите [Tailscale](https://tailscale.com) (тот же аккаунт,
   что на компьютере) — доступ извне только через него, порты наружу не открываются.
3. Установите `agent-hub-android.apk` (кнопка выше) и отсканируйте QR
   «Приложение Android» камерой — ссылка `agenthub://…` откроет чат. Либо просто
   откройте ссылку «Браузер / PWA» в Chrome и добавьте на главный экран.

Ссылка содержит секретный токен — не публикуйте её; сбросить токен можно в той же команде.

## Установка

1. Скачайте `.vsix` под свою систему кнопкой выше (все версии — в
   [Releases](https://github.com/marsevafin-boop/X4CodeVSCODE/releases)).
2. Установите:
   - терминал: `code --install-extension agent-hub-<платформа>.vsix`
   - или из VS Code: **Extensions → «…» → Install from VSIX…**
3. Перезапустите VS Code — в боковой панели появится иконка чата **Agent Hub**.

### Требования

- Установленные и залогиненные CLI-агенты на машине, где работает extension host
  (при Remote-SSH — на сервере):
  - `claude` — [Claude Code](https://docs.claude.com/en/docs/claude-code/overview) (подписка Claude Max);
  - `codex` — [Codex CLI](https://github.com/openai/codex) (аккаунт ChatGPT).
- В окружении **не должно быть** `ANTHROPIC_API_KEY` — иначе биллинг Claude
  уйдёт в pay-as-you-go вместо подписки.

## Возможности

- 💬 Чат со стримингом, переключатель Claude ⇄ GPT, очередь сообщений «вдогонку»;
- 📁 Проекты: папка, GitHub-репозиторий, ветка, сервер (host/логин/порт,
  пароль — в Keychain), проверка SSH/SFTP/FTP из настроек;
- 🛡 Карточки подтверждений операций + allowlist безопасных команд; режимы
  acceptEdits / YOLO (dangerously-skip-permissions) с переключателем в статус-строке;
- ❓ Вопросы агента (AskUserQuestion) — карточкой с кнопками-вариантами;
- 🕘 История сессий на проект: возврат, удаление, восстановление после перезапуска;
- 📝 Карточка «Задача · заметки»: цель, область, критерии, проверки и следующий шаг;
- ✍ Журнал сессий в `docs/journal/` — общая память между агентами и машинами;
- 📎 Вложения: файлы, скриншоты из буфера (Cmd+V), drag&drop;
- 📊 Индикатор модели и точной занятости контекста (живой, по каждому шагу);
- ⚙ Все настройки внутри панели + экспорт/импорт всех настроек в JSON.

«Проверить поля формы» проверяет реквизиты указанного в форме проекта без
сохранения. При заданном пароле проверяется именно пароль; успешный вход по
ключу его не подменяет. Изменение реквизитов сбрасывает результат проверки.
Для применения настроек к агенту нажмите «Сохранить». На каждом новом ходе,
включая продолжение сессии, агент получает актуальную карточку проекта и
одинаковый пароль в `SSHPASS`, `AGENT_HUB_SERVER_PASSWORD`, `LFTP_PASSWORD`.
`sshpass -e` читает `SSHPASS`; значения секретов в карточку не добавляются.
SSH/SFTP-команды в карточке агента и проверка соединения используют общий
набор параметров аутентификации. Парольный вход исключает подмену проверкой
ключа или переиспользованием старого соединения. Если порт в проекте не задан,
сохраняется его выбор из настроек OpenSSH, включая SSH-алиасы.

«Добавить проект» всегда создаёт новую запись, даже если выбранная папка уже
используется. Название, сервер, пароль и история чата у записей независимые;
файлы, ветка git и файловый журнал в общей папке остаются общими. Старые записи
сохраняют свои доступы и историю. Несколько чатов могут одновременно работать
в одной папке; при пересечении ходов автоматические Git-операции пропускаются,
чтобы не смешивать изменения. Удаление записи из списка не затрагивает другие записи той же
папки; удаление самой папки недоступно, пока её использует другой проект.

В ⚙ порядок проектов можно менять перетаскиванием за ↕, кнопками ↑/↓ или
стрелками клавиатуры на ручке переноса. Порядок сохраняется после перезапуска
и применяется к списку проектов и селекторам в чатах.

Кнопка 📦 у проекта переносит его папку целиком в соседнюю `Archive` и скрывает
запись из активного списка. В разделе «📦 Архив» можно вернуть проект на прежнее
место вместе с настройками и историей; занятый исходный путь не перезаписывается.
Несколько профилей одной папки архивируются и восстанавливаются вместе.
Перед перемещением нужно дождаться завершения агентов в этой папке во всех
окнах и закрыть её, если она открыта как рабочая папка VS Code. Архивные плитки мультичата
сохраняются и предлагают восстановить проект.

Мультичат сохраняет состав и порядок плиток, выбранные проекты, сессии и
провайдеров. После перезапуска VS Code открытая вкладка восстанавливает свою
раскладку; при ручном открытии используется последняя раскладка этого workspace.
Пустая доска также сохраняется — новые чаты добавляются кнопкой «＋ Чат».
Продолжить сохранённую сессию можно отправкой нового сообщения в её плитке.
Записи сохранённых досок защищены от автоматической очистки истории;
при необходимости их можно удалить вручную через историю сессий.

В ⚙ → «Агент, модель и effort по умолчанию» можно выбрать общий провайдер:
Claude, GPT (Codex) или запоминание последнего выбора. Общие модели и effort
задаются отдельно для каждого провайдера; список effort учитывает выбранную
модель, если её возможности известны из каталога установленного CLI.

Для запуска без сохранённой сессии, создания проекта и создания чата/сессии
есть независимые правила: общие настройки, сохранение текущего/последнего
выбора или собственный профиль с провайдером, моделью и effort. Пустые поля
собственного профиля наследуют общие настройки провайдера. В качестве модели
можно выбрать подсказку из каталога или ввести свой идентификатор.

Выбор провайдера обычного чата теперь сохраняется вместе с сессией.
Восстановленные обычные и мультичаты сохраняют свои настройки, включая effort;
правило запуска применяется к новому контексту без привязанной сессии.
Правила включаются в экспорт/импорт настроек. Пока новое правило не задано,
используется совместимое наследование текущего выбора.

Кнопка «⤢ Больше места» в шапке мультичата включает компактный режим:
уменьшает отступы и промежутки, убирает широкие боковые поля и включает
штатный Zen Mode VS Code, освобождая место за счёт боковых и нижней панелей.
Шрифты, крупные адреса серверов, черновики и вручную выбранная высота ввода
сохраняются. Режим запоминается для этого workspace и применяется при следующем
открытии доски. Вернуть обычный вид можно той же кнопкой или `Esc Esc`.
При закрытии доски интерфейс редактора возвращается, а предпочтение режима
остаётся для следующего открытия. Доступны также команды палитры
«Agent Hub: Компактный режим мультичата — больше места» и
«Agent Hub: Выйти из компактного режима».

Режим использует текущие настройки Zen Mode, включая `zenMode.fullScreen`,
`zenMode.showTabs`, `zenMode.hideStatusBar` и `zenMode.hideActivityBar`;
настройки редактора и файлы проекта он не перезаписывает. Управление Zen
переходит к кнопке на время компактного режима; обычное центрирование,
включённое вручную до входа, может быть снято для освобождения ширины.

Ответ на асинхронный вопрос Codex передаётся в текущий ход через канал
корректировки. Подтверждённая доставка не запускает дополнительный промпт
после завершения работы. Если канал уже закрыт, ответ может начать один новый
ход в исходной сессии; при смене сессии устаревший ответ не отправляется.
Неоднозначная ошибка доставки показывается без автоматического повтора.

### Заметки о задаче

Свёрнутая карточка **«Задача · заметки»** относится к конкретной сохранённой
сессии и остаётся с ней при перезапуске и смене провайдера. Заполните нужные
поля и нажмите **«Сохранить»**. Лимит — 2 000 символов на поле и 12 000 суммарно.
Это ваши записи: они не подтверждают выполнение тестов, ревью или выпуска.

Сохранение не вызывает модель и не добавляет заметки к следующим промптам.
**«Вставить в сообщение»** дописывает их к текущему черновику; проверить и
отправить его нужно обычным способом. Сбой сохранения оставляет текст в форме.
При конфликте версий можно сравнить сохранённый вариант, загрузить его либо
явно сохранить свои правки поверх него.

Проверка конфликтов действует между представлениями одного extension host
(панель, вкладка, плитки чатов). Одновременное редактирование одной сессии из
разных окон VS Code пока не имеет атомарной защиты: они используют общий
session store. Для такой работы нужна отдельная доработка хранения.

### Правила разрешения Bash

`autoAllowBash` проверяет одну простую команду. Базовые правила `git status`,
`git diff`, `git log`, `ls` допускают только поддержанные параметры, например
`git status -s`, `git diff --stat`, `git log --oneline -5`, `ls -la`.
Составные команды, перенаправления, подстановки, кавычки и неизвестные
параметры требуют карточки подтверждения. Другие настроенные правила
сопоставляются с полным набором аргументов; добавление `Bash` в
`autoAllowTools` эту проверку не отключает.

Это проверка текста команды; она не проверяет доверие к найденному executable,
PATH или конфигурации Git. Явно выбранные режимы YOLO/bypass сохраняют свою
прежнюю семантику.

## Перенос настроек между машинами

⚙ → «⬇ Экспорт в JSON» на старой машине → «⬆ Импорт из JSON» на новой.
Пароли серверов не экспортируются (хранятся в системном Keychain) — задаются
заново. Пути проектов при переносе между ОС поправьте в JSON или через ⚙.

## Сборка из исходников

Нужен Node.js 22 или новее. Версия упаковщика `@vscode/vsce` закреплена в
devDependencies; отдельно устанавливать его не требуется.

Для цепочки упаковщика `vsce 4.0.0 → Azure Identity 4.14.0` закреплён
MSAL Node 7.1.1, исправляющий GHSA-xcx6-jx8p-x3h5. Совместимость используемого
адаптером API проверена статически; упаковка VSIX проверяется отдельно.
Этот override относится только к dev-инструменту. Авторизация публикации
в Marketplace с ним не проверялась; перед добавлением такого workflow
нужно проверить её и пересмотреть override при обновлении зависимостей.

```bash
npm ci
npm test                 # регрессионные тесты без запуска реальных агентов и SSH
npm run typecheck        # проверка TypeScript
npm run build            # esbuild: dist/extension.js + dist/webview.js
npm run package -- --target darwin-arm64  # выбрать платформу extension host
```

Команда упаковки сама запускает сборку. Пакет остаётся `UNLICENSED`;
`--skip-license` позволяет собрать его без отдельного файла лицензии.
Workflow **Extension checks** на push и pull request проверяет типы, тесты,
сборку и упаковку на Linux, macOS и Windows. VSIX для платформы runner
сохраняется как артефакт запуска на 14 дней. Публикацию релиза этот workflow
не выполняет. Android собирается отдельным существующим workflow.

Отладка: открыть папку в VS Code → F5 (Extension Development Host).

## Архитектура

`src/extension.ts` → `src/ChatViewProvider.ts` (протокол `src/shared/protocol.ts`,
журнал `src/journal.ts`) → бэкенды `src/agents/{claudeBackend,codexAppServerBackend}.ts`
за единым интерфейсом `AgentBackend`; UI — React в `webview/`.
Codex работает через `app-server`, с резервным запуском через `codexBackend.ts`.
События субагентов отделены от основного хода: завершение субагента не
останавливает основной ответ и не переводит весь чат в состояние «готово».
Если сохранённый тред Codex открыт другим клиентом, расширение автоматически
продолжает работу в отдельной ветке с копией его сохранённой истории. Исходный
чат остаётся открытым; завершать ChatGPT или другие процессы Codex не требуется.
Восстановление выполняется до отправки задачи и сохраняет текущие настройки
модели и песочницы. Собственные процессы расширения учитываются с запуска;
следующий ход ждёт подтверждённого завершения предыдущего процесса.
Ветвление использует `thread/fork` из [официального протокола Codex](https://learn.chatgpt.com/docs/app-server).
Спецификация и замысел — `ai-dev-environment.md`.
